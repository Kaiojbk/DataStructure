一、数据结构的基本概念与术语
================================================================

★★★ 数据、数据元素、数据项、数据对象(易混淆,选择题常考)

   · 数据(Data)
       信息的载体,是描述客观事物属性的数、字符及所有能输入到
       计算机中并被程序识别和处理的符号的集合。

   · 数据元素(Data Element)        ← 数据的基本单位
       数据的基本单位,通常作为一个整体进行考虑和处理。
       一个数据元素可由若干数据项组成。

   · 数据项(Data Item)              ← 数据的最小单位 【易错】
       构成数据元素的不可分割的最小单位。

       ⚠ 记法:元素是"基本单位",项是"最小单位"。这两个词极易记反,
         是选择题的经典设错点。

   · 数据对象(Data Object)
       具有相同性质的数据元素的集合,是数据的一个子集。

   · 数据结构(Data Structure)
       相互之间存在一种或多种特定关系的数据元素的集合。

   【层次关系】
       数据  >  数据对象  >  数据元素  >  数据项
       例:全校学生表 → 一名学生(元素) → 学号/姓名(数据项)


★★ 数据类型与抽象数据类型(ADT)

   · 数据类型(Data Type)
       一个值的集合和定义在此集合上的一组操作的总称。
         - 原子类型:值不可再分(如 int、char)
         - 结构类型:值可再分解(如 struct、数组)

   · 抽象数据类型(ADT)
       抽象数据组织及与之相关的操作,与具体实现无关。
       描述形式:<数据对象 D,数据关系 S,基本操作 P>
       特点:只关心"做什么",不关心"怎么做"。

       ⚠ 考点:ADT 的定义与实现分离,同一 ADT 可有多种实现
         (如"线性表"这个 ADT,顺序表和链表是两种实现)。


★★★ 数据结构三要素(全章骨架,必须理清)

   1. 逻辑结构 —— 数据元素之间的逻辑关系,与存储无关

        线性结构:线性表、栈、队列、串、数组      —— 一对一
        树形结构:树、二叉树                      —— 一对多
        图形结构:图                              —— 多对多
        集合    :元素间无其他关系,仅同属一个集合 —— 无关系

        (树、图、集合统称非线性结构)

   2. 存储结构(物理结构)—— 数据结构在计算机中的表示(映像)

        · 顺序存储:逻辑相邻的元素存放在物理位置相邻的存储单元
             优点:可随机存取,存储密度高
             缺点:插入删除需移动大量元素;需预分配空间,
                  可能溢出或浪费(无外部碎片)

        · 链式存储:借助指针表示元素间的逻辑关系
             优点:插入删除方便,不需连续空间,无碎片问题
             缺点:只能顺序存取;指针域占用额外空间

        · 索引存储:建立附加索引表(索引项 = 关键字 + 地址)
             缺点:索引表占额外空间,增删时需同步修改索引表

        · 散列存储:根据关键字直接计算出存储地址(哈希存储)

   3. 数据的运算 —— 施加在数据上的操作(增、删、改、查等)
       运算的定义针对逻辑结构,运算的实现针对存储结构。

   ⚠ 高频易错点:
     (1) 逻辑结构独立于存储结构,存储结构是逻辑结构在计算机中的实现。
     (2) 同一种逻辑结构可有多种存储结构
         (线性表 → 顺序表 / 链表)。
     (3) 顺序存储 ≠ 线性结构。顺序存储同样可以表示非线性结构,
         例如完全二叉树可以用一维数组存储。
     (4) "逻辑结构与存储无关"是说逻辑结构不依赖于具体的存储方式,
         而不是说逻辑结构与存储没有联系。


================================================================
二、算法及其特性          ★★★ 高频,几乎每年必考
================================================================

★★★ 算法的定义与五大特性

   算法(Algorithm):对特定问题求解步骤的一种描述,
   是指令的有限序列。

   五大特性:
     ① 有穷性 —— 算法必须在执行有穷步之后结束,
                 且每一步都在有穷时间内完成
     ② 确定性 —— 每条指令有确切含义,无二义性;
                 相同输入只能得到相同输出
     ③ 可行性 —— 算法中的操作都可以通过已实现的基本运算
                 执行有限次来实现
     ④ 输入   —— 有零个或多个输入
     ⑤ 输出   —— 有一个或多个输出(没有输出的算法毫无意义)

   ⚠ 最高频陷阱:算法 ≠ 程序
       程序可以不满足"有穷性"(如操作系统、服务进程长期运行),
       但算法必须满足有穷性。
       这是"算法与程序的区别"这一考点的标准答案。


★★ 算法设计的目标(衡量好算法的标准)

   ① 正确性   —— 能正确解决求解问题
   ② 可读性   —— 便于人们理解和交流
   ③ 健壮性   —— 输入非法数据时能作出适当反应或处理,
                 不会产生莫名其妙的结果
   ④ 效率与低存储量需求 —— 时间复杂度低、空间复杂度低


================================================================
三、算法效率的度量 —— 时间复杂度        ★★★ 全书最高频考点
================================================================

★★★ 大 O 记号与计算规则

   【定义】T(n) = O(f(n)) 表示存在正常数 C 和 n₀,
     使得当 n ≥ n₀ 时,恒有 T(n) ≤ C·f(n)。
     即:只保留最高阶项,忽略系数与低阶项。

   【计算规则】
     · 用常数 1 取代运行时间中的所有加法常数
     · 只保留最高阶项,去掉系数
          3n² + 5n + 7  →  O(n²)
     · 嵌套循环:各层循环次数相乘
     · 顺序执行的语句:取最大者(加法规则)

   【常考循环模式 —— 要能秒判】
     for(i = 0; i < n; i++)                        → O(n)
     for(i = 0; i < n; i++) for(j = 0; j < n; j++) → O(n²)
     for(i = 1; i <= n; i *= 2)                    → O(log₂n)
     for(i = 1; i <= n; i++) for(j = 1; j <= i; j++) → O(n²)
          ⚠ 内层上界是 i 不是 n,但总体仍是 n² 量级
     while(i <= n) i = i * 3;                      → O(log₃n)
     x = n; while(x >= 1) x = x / 2;               → O(log₂n)

   ★★★ 【常见复杂度量级由小到大】(必背!选择题常考排序)
       O(1) < O(log₂n) < O(n) < O(n·log₂n)
             < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)

   【三种情况】
     · 最坏时间复杂度 —— 最常用
     · 最好时间复杂度
     · 平均时间复杂度
     ⚠ 若无特殊说明,考研中的"时间复杂度"一律指最坏情况。

   ⚠ 易错点:
     (1) 复杂度是渐近的,不关心具体常数大小;
         O(2n²) 与 O(n²) 是同一量级。
     (2) 代码长短与复杂度无关,只看执行次数随 n 的增长趋势。
     (3) 两个算法的时间复杂度相同,不代表实际运行速度一样。


★★ 空间复杂度

   【定义】算法所需存储空间 S(n) 是问题规模 n 的函数,S(n) = O(g(n))。

   【常考情况】
     · 算法所需辅助空间是常量 → O(1)(称原地工作/就地算法)
     · 递归算法需考虑递归工作栈深度:
       递归深度为 n 的算法,空间复杂度为 O(n)
       例:斐波那契递归求值 —— 时间 O(2ⁿ),空间 O(n)(栈深)

   ⚠ 易错点:
     空间复杂度只计算算法额外需要的辅助空间,
     不包括输入数据本身所占用的空间。


★★ 时间复杂度与空间复杂度的关系

   二者往往相互矛盾:可以把时间换来空间,也可用空间换时间。
   一般来说,更看重时间复杂度(时间比空间更宝贵)。

四、复习优先级速查表
================================================================

   【必须拿下 —— ★★★】
     ① 时间复杂度计算(每年必考,复习时间投入应最多)
     ② 逻辑结构与存储结构的区分与联系
     ③ 数据项是"最小单位"、数据元素是"基本单位"
     ④ 算法五大特性,尤其"有穷性"
     ⑤ 算法 ≠ 程序(有穷性是分界线)
     ⑥ 常见复杂度量级的大小排序

   【需要理解并能应用 —— ★★】
     ⑦ 四种存储结构的特点与优缺点对比
     ⑧ 空间复杂度分析(递归栈深度、是否原地工作)
     ⑨ 算法设计目标的四条
     ⑩ 抽象数据类型 ADT 的定义与"定义实现分离"的思想

   【过一遍有印象 —— ★】
     ⑪ 数据、数据对象、数据类型的精确定义
     ⑫ 数据的运算(定义针对逻辑结构,实现针对存储结构)
